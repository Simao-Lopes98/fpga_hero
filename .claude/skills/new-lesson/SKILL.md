# New Lesson Scaffold

Create a new lesson directory following the canonical workflow in `ai_OS/HANDOVER.md` and `ai_OS/README.md`. Use `ai_OS/template_project/` as the reference structure.

## Inputs needed

- **Project name** (snake_case, no number prefix) — ask the user if not given.
- **Module ports** — if the user described the lesson (e.g. "a Mealy FSM with 2 buttons and 5 LEDs"), infer the port signature. Otherwise default to the template: `input clk, input [1:0] pmod, output reg [4:0] led`.

## Strict sequential steps — do NOT reorder

1. **Determine the folder number.** List existing `NN_*` directories and pick the next increment, zero-padded to 2 digits. Create `NN_projectname/`.

2. **Create `projectname.pcf`** — copy the structure from `ai_OS/template_project/template_project.pcf`. Update the header comment to the project name. Keep the fixed ICEStick pins: clk=21; LEDs 99/98/97/96/95; PMOD pins 78/79 with `set_io -pullup yes`. Only include the `set_io` lines for ports the module actually uses (e.g. drop `led[4]` if the module only has a 4-bit `led`).

3. **Create `projectname.v` — STUB ONLY, no implementation.** Block comment with `/* */` describing the lesson, then the `module projectname (...);` port list and `endmodule` with an empty body. Use `snake_case`. Example:
   ```verilog
   /*
   <Project name> module - <one-line description>
   */


   module projectname (
       input               clk,
       input      [1:0]    pmod,
       output reg [4:0]    led
   );


   endmodule
   ```

4. **Create `.gitignore`** with exactly:
   ```
   _build
   .DS_Store
   ```

5. **Do NOT create `apio.ini` manually.** ⚠️ It must be generated by APIO in the next step.

6. **Generate the APIO config** by running in the new folder:
   ```bash
   cd NN_projectname && apio create -b icestick
   ```
   This auto-creates `apio.ini` with `top-module = main`.

7. **Fix `apio.ini`** — change `top-module = main` to `top-module = projectname` so it matches the module name in the `.v` file.

## Common mistakes to avoid

- ❌ Creating `apio.ini` by hand before step 6.
- ❌ Forgetting to update `top-module` in step 7.
- ❌ Module name in `.v` not matching `top-module`.
- ❌ Adding implementation logic in step 3 — it must be a bare stub. This is a learning repo; the user writes the logic.

## After scaffolding

Report the created files and confirm `top-module` matches. Do **not** implement the lesson logic unless explicitly asked — leave the stub for the user to fill in. If `apio create` isn't available in the environment, create `apio.ini` from the template form yourself and flag that step 6 was substituted.
